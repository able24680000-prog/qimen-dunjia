# 奇门网站开发记忆

更新日期：2026-07-07

## 0. 页面设计确认流程（2026-07-13）

- 只要涉及首页方向、整体视觉风格、排盘页结构、知识页阅读结构等可见页面设计改动，先用概念图或可点击的网页预览向用户说明拟议效果。
- 概念预览应使用中文，明确标出将改变的区域、默认收起/展开状态和关键操作位置；不以代码片段作为确认材料。
- 用户确认视觉方向后，才修改正式页面代码。未确认时只可做只读诊断、概念稿或与视觉无关的安全维护。
- 每次交付时以“改动效果、涉及页面、验收结果、遗留问题”说明，不要求用户阅读 JSX/CSS。

## 1. 一句话记忆

这是一个“可信排盘 + 知识学习 + 本地复盘”的奇门遁甲网站，不是承诺结果的预测软件。

## 2. 当前产品决策

- 主项目是 `qimen-website`。
- 技术路线继续用 React + Vite，不重开项目。
- 排盘计算继续放前端，用户问题默认只在本地处理。
- 本地复盘样本使用 `localStorage`，短期不接登录和云端数据库。
- 首页负责建立气质与入口，排盘页负责工具效率，知识页负责解释和 SEO，关于页负责边界。
- `HomeConcept.jsx` 是视觉实验，不等于正式首页。

## 3. 表达口径

必须坚持：

- “参考置信度”只表示盘内信号集中，不表示现实必然发生。
- 重大事项必须以现实证据和专业意见为准。
- 一盘一问，问题越清楚，复盘越有意义。
- 断语要写成可验证观察点，而不是绝对化结论。
- 样本不足时不宣称稳定准确率。

避免：

- 必成、必败、必中、必然。
- 用神秘感压过可读性。
- 把 70% 写成单盘保证。
- 用视觉特效掩盖排盘依据。

## 4. 代码记忆

- `src/lib/qimen.js` 是核心算法文件，改动前后必须跑 `npm run verify:qimen`。
- `src/knowledge` 是知识内容来源，改动后必须跑 `npm run verify:knowledge`。
- `Divination.jsx` 很大，后续改排盘页时优先就地理解，再小步拆分。
- `App.jsx` 当前定义了导航和页脚，但 `src/components` 里也有对应文件，后续要统一来源。
- `index.css` 包含正式主题和概念首页样式，改首页时要留意影响范围。
- PowerShell 读取中文文件时需要用 `Get-Content -Encoding UTF8`，否则可能显示乱码。

## 5. 已知工程风险

- 缺少真正的测试框架，当前靠脚本式验证。
- 算法基准样本还不够覆盖所有边界。
- 知识数据量会影响包体，后续要继续懒加载。
- 复盘样本保存在浏览器本地，清缓存会丢失。
- 根目录有多个历史 HTML/MD 小样，容易混淆正式入口。

## 6. 后续开发顺序

### 阶段 0：工程健康

- 确认 build、lint、verify 脚本。
- 清理 README 和记忆文件。
- 建立上线前检查表。

### 阶段 1：首页收束

- 正式首页只保留一个清楚入口：进入排盘。
- 视觉保持沉静、精密、可信。
- 概念页继续作为实验路由或归档。

### 阶段 2：排盘页降噪

- 基础字段默认展示：时间、问题、目的、起局。
- 高级字段折叠：农历、日/月/年家、茅山法、出生年。
- 宫位详情按“判断、依据、风险、行动、复盘”组织。

### 阶段 3：算法验证

- 增加节气边界案例。
- 增加 23 点子时案例。
- 增加茅山法和拆补法对照。
- 记录 `taobi-src` 与正式实现的差异。

### 阶段 4：上线检查

- 桌面、平板、手机三端检查。
- 首页、排盘页、知识页、关于页路径检查。
- 免责声明和隐私说明检查。
- 导出图片、保存样本、CSV、知识更新建议流程检查。

## 7. 给后续 Codex 的提示

每次接手这个项目时，先看：

1. `AGENTS.md`
2. `docs/architecture.md`
3. `docs/development-memory.md`
4. `qimen-website/README.md`

如果用户说“继续奇门网站”，默认先确认当前要做的是：

- 首页视觉
- 排盘功能
- 算法准确性
- 知识库
- 复盘样本
- 上线部署

不要一上来重构全项目。这个项目已经有可运行基础，后续要小步稳定推进。
