# Codex 网页效果提升工作流

> 用途：让 Codex 做网页时，不再“一句话生成页面”，而是按设计、规范、实现、验收的闭环推进。适用于奇门首页，也适用于后续品牌页、专题页、互动视觉页。

---

## 一、核心原则

网页效果差，通常不是代码能力问题，而是工作流太短。以后默认采用：

```text
定方向 -> 做设计 -> 提规范 -> 写组件 -> 补交互 -> 浏览器验收 -> 复盘沉淀
```

不要直接说“做高级点”“漂亮点”。必须先确定页面气质、受众、参考、限制、交互和验收方式。

---

## 二、任务启动流程

### 1. 先做设计读取

Codex 开工前必须先输出一句设计读取：

```text
我把这个页面理解为：面向谁的什么页面，应该是什么气质，不能落入什么俗套。
```

奇门首页示例：

```text
我把这个首页理解为：面向高审美用户的东方术数视觉作品，不是算命工具页；气质应是宣纸、版心、日影盘、工程图纸感，避免玄学特效和功能卡片网页。
```

### 2. 再定三项设计拨盘

每次网页任务都先写清：

| 拨盘 | 含义 | 奇门首页建议 |
|---|---|---|
| 视觉变化度 | 对称稳定还是更有艺术构图 | 6/10，克制但不能模板 |
| 动效强度 | 静态、微动、还是电影感 | 5/10，慢、柔、有呼吸 |
| 信息密度 | 留白艺术品还是功能界面 | 3/10，数据轻量 |

### 3. 明确红线

每个项目都要写“不要做什么”。没有红线，Codex 容易默认生成 AI 模板。

奇门首页红线：

- 不做大红大金中国风
- 不做粒子、霓虹、云雾、龙纹、太极堆砌
- 不做卡片、tooltip、数据表格式功能页
- 不做五行色满屏流动
- 不做快节奏动效，周期低于 4 秒的一律退回

---

## 三、推荐 Skills / 插件使用顺序

按需使用，不堆砌。

### 设计判断

- `design-taste-frontend`：去 AI 感，判断版式、字体、配色、常见俗套。
- `impeccable`：做审美审查、动效审查、响应式和可访问性检查。
- `product-design:get-context`：复杂产品或流程页，先补全设计上下文。

### 视觉探索

- `product-design:ideate`：做多方向视觉探索。
- `imagegen`：当页面需要真实视觉参考图、质感图、背景图或视觉概念稿时使用。
- `screenshot-to-ui / image-to-code` 类能力：有截图或设计稿时，先还原结构，再优化。

### 实现与验收

- 浏览器控制 / Playwright：必须用于真实预览、桌面和移动截图、console 检查。
- 组件库技能：只有当项目需要长期维护时再上，不要为了小样引入复杂依赖。

奇门首页当前选择：

```text
design-taste-frontend + impeccable + Playwright 浏览器验收
```

暂不引入框架、Tailwind、GSAP，先用纯 HTML/CSS/JS 做可控小样。

## 四、提示词公式

以后给 Codex 的网页任务，按这个公式写：

```text
场景：
这个页面是什么，给谁看，用户第一眼应该感到什么。

风格：
主视觉气质、参考对象、字体、颜色、材质、空间感。

内容：
页面必须出现哪些信息，哪些信息不要出现。

交互：
悬停、点击、滚动、动效节奏、状态变化。

限制：
不要新增什么，不要使用什么风格，不要破坏什么文件。

验收：
桌面、移动、console、截图、动效周期、视觉红线。
```

奇门首页示例：

```text
场景：做奇门遁甲首页，不是算命工具，而是东方术数视觉作品。
风格：宣纸、宋版版心、日影盘、天圆地方、工程图纸细线，大量留白。
内容：左侧竖排题字、中央日影盘、九宫、洛书轨迹、入口文字。不要数据表格。
交互：洛书光点 24 秒循环，指针联动，斜光 22 秒扫过，落宫高光呼吸。
限制：不做粒子、霓虹、五行彩色乱流、卡片 tooltip、快动效。
验收：1920×1080 和 375×667 截图，console 无错误，动效周期全部大于 4 秒。
```

## 五、实现分步

### Step 1：先出结构，不急着美化

先画页面骨架：

- 首屏信息分区
- 主视觉位置
- 导航位置
- CTA 或入口
- 移动端折叠方式

可用 ASCII 草图或最小 HTML。

### Step 2：建立设计 Token

先定义变量，再写细节：

- 背景色
- 主文字色
- 辅助文字色
- 线色
- 强调色
- 字体族
- 间距
- 动效周期
- 缓动曲线

奇门首页必须把纸色、墨色、朱砂、线色、光影强度、动效周期写成 CSS 变量。

### Step 3：完成静态画面

静态必须先美。动效不能用来掩盖画面不成立。

验收标准：

- 截一张静图也像设计稿
- 主次清楚
- 留白舒服
- 文字不挤
- 没有 AI 模板味

### Step 4：只加必要动效

每个动效必须回答一句话：

```text
这个动效在表达什么？
```

奇门首页：

- 洛书轨迹表达时局流转
- 指针表达日影定时
- 落宫高光表达当下被点亮
- 自然光表达纸面时间感

### Step 5：真实浏览器验收

每次重要改动后检查：

- 桌面 1920×1080
- 移动 375×667
- console error/warning
- 横向溢出
- 文字重叠
- 动效是否过快
- 页面静止是否仍然好看

## 六、浏览器视觉 QA 清单

### 桌面端

- [ ] 首屏主体是否有明确视觉中心
- [ ] 重要内容是否在第一眼被看到
- [ ] 留白是否有节奏，不是空
- [ ] 导航是否一行显示
- [ ] 字体层级是否清楚
- [ ] 动效是否不抢主体

### 移动端

- [ ] 没有横向滚动
- [ ] 标题不压住主视觉
- [ ] 主视觉不被裁得失去意义
- [ ] 小字可读，必要时隐藏非核心注记
- [ ] 点击区域够大

### 动效

- [ ] 周期全部大于 4 秒
- [ ] 没有眩晕、闪烁、廉价发光
- [ ] transform / opacity 优先，不动画布局属性
- [ ] 支持 `prefers-reduced-motion`
- [ ] 动效暂停瞬间仍然是一张好图

## 七、奇门首页专用规则

### 本项目审美方向

```text
宋版术数书页 + 宣纸版心 + 日影盘 + 九宫秩序 + 洛书流转
```

### 当前最佳动效组合

| 类型 | 采用 | 周期 |
|---|---|---|
| 九宫流转 | 洛书轨迹 | 24s |
| 九宫流转 | 指针流转 | 36s 级别 |
| 光影变化 | 自然光扫纸 | 22s |
| 光影变化 | 落宫高光 | 随洛书每宫约 3s |

### 当前不建议做

- 星移宫换：容易像游戏棋子移动
- 五行流转：容易变彩色玄学特效
- 刻度流光：容易像科技仪表盘
- 全局强呼吸：容易整页忽明忽暗

## 八、交付标准

以后 Codex 完成网页任务，最终汇报必须包含：

```text
做了什么：
改了哪些文件，核心效果是什么。

验证了什么：
语法、浏览器、桌面、移动、console、动效。

没做什么：
哪些范围故意没碰，哪些测试因环境限制没跑。

下一步建议：
只给 1-2 个最值得继续的方向。
```

```text
请按“设计读取 -> 设计拨盘 -> 红线 -> 结构草图 -> 实现计划 -> 验收方式”的顺序处理这个网页任务。

场景：
[写页面目标和受众]

风格：
[写参考、气质、材质、字体、配色]

内容：
[写必须出现和必须隐藏的信息]

交互：
[写悬停、点击、动效、响应式]

限制：
[写不要新增功能、不要使用的风格、不要改的文件]

验收：
[写桌面尺寸、移动尺寸、console、截图、性能、可访问性]

要求：
先读项目文件，再输出理解与计划。确认后再写代码。每完成一个关键动效都要浏览器验收。
```
